# 参考本机 deepin-movie 的界面改造方案

## 目标与依据

目标是让当前工程在布局、色彩、控件、菜单、设置和交互状态上遵循本机 deepin-movie 的设计语言。

本次实际启动并检查的是玲珑安装的 `org.deepin.movie 6.5.53.1`。依据包括用户提供的首页截图、本机应用的浅色/深色首页、主菜单、右键菜单、设置窗口、字幕设置、播放状态和展开的播放列表。使用工程内的 VP9/Opus 合成样片核对播放布局；本机应用随附的中文使用手册用作交互行为的补充依据。手册中的历史截图不作为当前版本的尺寸依据。

本文件区分“实测参考”和“工程建议”。像素值受系统主题、缩放、截图位置和透明合成影响，不代表 DTK 的官方设计规范。

第 1–8 节保留改造前的分析及原型记录；当前工程已按本方案完成第一、第二阶段，实际实现与验证见第 9 节。

## 1. 需要改变的设计方向

原生参考呈现的是一个桌面播放器：内容区域安静，常用操作集中在底部，复杂功能通过菜单和设置窗口展开。

当前工程更接近 Web 工具界面：标题栏有品牌文字和多个文字操作，首页有介绍文案和三枚按钮，设置与媒体库采用右侧抽屉。全面参考 deepin-movie，需要重组这些区域，单靠修改 CSS 配色无法完成。

### 实际观察到的结构

| 区域 | 本机 deepin-movie | 当前工程需要的变化 |
| --- | --- | --- |
| 标题栏 | 左侧小应用图标；播放时文件名居中；右侧主菜单与系统窗口按钮 | 收起“打开 / 媒体库 / 更多”这组常驻文字入口；标题独立居中 |
| 空白首页 | 中央只有较大的应用图标；浅色为白底，深色为黑底 | 去除常驻营销式标题、格式说明和三枚入口按钮；保留拖放和快捷打开 |
| 底部控制 | 首页就可见；左侧上一项/播放/下一项组成一块圆角面板 | 底栏改为常驻；空状态下播放按钮负责打开文件 |
| 进度与时间 | 有媒体时位于底栏中间，与播放控件同排；两端为当前/总时间 | 将现有通栏进度条和播放时间重新组合 |
| 右侧工具 | 独立圆角方块，依次为全屏、音量、投屏、播放列表 | 对齐尺寸和排列；当前无投屏能力，使用已有“播放调节”入口占据相应工具位置 |
| 主菜单 | 打开文件、打开文件夹、设置、主题、帮助、关于等 | 合并打开菜单与更多菜单，主题可直接从菜单访问 |
| 右键菜单 | 打开 URL、播放模式、倍速、画面、声音、字幕、截图、影片信息等 | 增加应用自己的上下文菜单，将低频操作按类别组织 |
| 设置 | 独立的居中窗口，左侧分类导航，右侧滚动内容和分组行 | 将右侧设置抽屉改为分类设置对话框 |
| 播放列表 | 从底部展开，覆盖画面大部分高度；左侧标题/数量，右侧列表 | 将右侧媒体库抽屉改为底部列表面板；保留工程现有历史和书签 |

## 2. 布局与尺寸

本次本机应用窗口截图为 `1700 × 1200` 物理像素，对应约 `850 × 600` 的逻辑尺寸。以下建议用 CSS px 实现，不直接复制 2 倍截图的物理尺寸。

| 项目 | 实测参考 / 建议起点 |
| --- | --- |
| 标题栏 | 约 50 px 高；左右点击区域约 50 px |
| 底部控制带 | 约 80 px 高；左右外边距约 16 px |
| 上一项/播放/下一项组合 | 约 120 × 50 px，圆角约 10 px |
| 右侧工具按钮 | 约 50 × 50 px，间隔约 10 px，圆角约 10 px |
| 中央应用图标 | 图形可见宽约 108 px；图像容器约 128 px |
| 顶栏图标 | 可见图形约 26 px |
| 普通工具图标 | 约 18–24 px；播放图标为实心 |
| 右键/主菜单 | 行高约 28–32 px，圆角约 10–12 px；文字左对齐 |
| 设置窗口 | 参考约 680 × 566 px；工程建议 720–800 px 宽，最大高度 86vh |
| 设置导航 | 参考约 190 px；工程建议 160–190 px |
| 底部列表 | 本机约从窗口 1/3 高度开始覆盖；建议可用高度的 60–68% |

工程版底栏建议结构：

```text
上一项 / 播放 / 下一项    当前时间 ─────进度───── 总时间    全屏  音量  调节  列表
```

宽窗口维持单排。较窄窗口先将进度时间移到控制行上方，继续保留常用操作；更窄时将低频工具收入菜单。避免把 850 px 的桌面排布强行压进 390 px 宽度，也不通过缩小到难以点击来适配。

## 3. 颜色与材质

### 从本机截图采样的颜色

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 空白内容区 | `#FFFFFF` | `#000000` |
| 标题栏 | `#FFFFFF` | `#282828` |
| 底部控制带/列表背景 | `#F7F7F7` | `#1F1F1F` |
| 控制按钮底色 | `#FFFFFF` | `#000000` |
| 设置分组底色 | 约 `#F8F8F8` | 需在正式实现中按深色层级补全 |
| 浅色选中项/设置导航 | `#1F6EE7` | 按主题定义对应选中态 |

主色是中性色，蓝色集中用于选中项、焦点和进度。普通播放按钮是黑/白实心图形，不再使用当前显著的蓝色圆形按钮。

建议引入按用途命名的变量：`--window-bg`、`--titlebar-bg`、`--toolbar-bg`、`--control-bg`、`--group-bg`、`--menu-bg`、`--text-primary`、`--text-secondary`、`--selection-bg`、`--focus-ring`。不要用一个 `--accent-strong` 同时承担按钮背景和浅色选中文字。

材料效果控制在菜单、对话框和悬浮控件上：轻描边、柔和投影、适度半透明。视频本身不施加模糊。右键菜单在彩色视频上需要足够不透明度保证文字可读；本机透明菜单的视觉效果可参考，但无需照搬其在强色背景上的低对比表现。

默认主题建议改成“跟随系统”，同时保留用户已有明确选择。播放画面及留黑区域始终使用黑底；浅色主题只改变应用外壳和空白页。

## 4. 按界面改造

### 4.1 标题栏

- 左侧保留应用图标；无媒体时中间不显示“未打开媒体”。
- 播放文件名独立居中，过长省略；不要因两侧区域宽度不同而偏移。
- 右侧单一主菜单。打开文件、文件夹、网络地址和应用设置从这里访问。
- 原生参考的应用图标带胶片和播放符号、少量体积感。工程应统一标题栏、空白页、桌面启动图标；在现有 SVG 上建立同一套图形语言。
- 原型中使用本机图标作为视觉参考，正式产品资产需要单独统一，不能把大图标简单替换为当前小号蓝底线性图标。

### 4.2 空白首页

- 大面积干净背景，中心仅保留应用图标。
- 中央图标和底部播放按钮都可以打开文件；`Ctrl+O`、主菜单和右键菜单提供同一操作。
- 文件夹和 URL 入口收入菜单。URL 使用独立小对话框，避免在首页常驻输入框。
- 格式支持说明移至帮助或文件选择提示；字幕拖放说明在相关操作时按需出现。
- 拖入视频时显示轻量边界和“松开以打开”；未打开视频就拖入字幕时显示可恢复提示。
- 空白页必须遮蔽或隐藏 WebGL canvas。当前透明内容被 canvas 的黑色清屏覆盖，仅修改 `.stage` 背景色不能保证浅色首页生效。

### 4.3 播放与底栏

- 控制带首页常驻，播放时显示中间进度；上一项/下一项按真实队列可用性禁用。
- 播放、暂停采用黑/白图形；蓝色用于进度拖块和活动工具。
- 当前时间放进度条左边，总时间放右边，采用等宽数字。桌面参考可使用 `00:00:00`；窄窗口可采用更紧凑格式。
- 进度保持实时订阅和拖动草稿逻辑；外观可参考本机细刻度轨道，但必须保证点击和键盘可用。
- 音量使用小弹层，支持点击、触摸、键盘；悬停仅作为桌面增强。
- 播放/暂停、音量改变可显示短时 OSD；缓冲和打开中使用轻量状态提示。
- 播放时的标题/底栏自动隐藏属于后续交互改造。现有工程只在全屏时隐藏；扩展到窗口播放时应避免改变 canvas 布局造成画面跳动。暂停、菜单、对话框、拖动进度和键盘焦点存在时保持控件可见。
- 本轮仅短样片，未完整测量原生自动隐藏时序；正式实现建议以约 2–3 秒作为可调整起点。

### 4.4 底部播放列表

- 以浮层覆盖播放区域，不挤压 canvas，也不将画面横向缩小。
- 左侧提供标题、数量和操作；右侧为紧凑文件行。
- 每行可包含序号、可选缩略图、名称、时长和移除按钮；当前播放行采用蓝底白字。
- 原生有视频缩略图，工程当前无列表封面管线。第一阶段使用统一文件图标，第二阶段再加入按需、带缓存的缩略图，不为每个文件常驻一个解码器。
- 保留“播放列表 / 历史 / 书签”，作为底部面板内的轻量导航；这是对工程既有功能的延续。
- 保留文件重新关联、URL 条目、拖拽排序、当前项来源和播放模式行为。位置改变不应重写列表数据逻辑。
- 收起面板后恢复视频完整可视区域；清空列表需要明确可撤销或确认的产品行为，不能误删本地文件。

### 4.5 主菜单与上下文菜单

主菜单负责应用级操作；右键菜单负责当前媒体操作。共享菜单项定义与动作调用，避免形成两套逻辑。

| 类别 | 工程已有能力的归属 |
| --- | --- |
| 文件 | 打开文件、打开文件夹、打开链接 |
| 播放 | 播放模式、倍速、上一项/下一项、逐帧 |
| 画面 | 适应方式、旋转、画面调节、视频轨 |
| 声音 | 声道、音轨、音量、音频调节 |
| 字幕 | 加载、选择、显示/隐藏、编码、字幕调节 |
| 截图 | 当前帧、15 帧剧情连拍、任务状态 |
| 信息 | 影片信息、播放统计入口 |
| 应用 | 主题、设置、帮助/快捷键说明 |

桌面外壳未支持的置顶/迷你模式、DLNA 投屏、光盘播放不应伪装成可用按钮。可以在具备相应能力后以同样风格接入。

菜单需支持边界避让、最多两层嵌套、Escape 关闭、方向键导航和焦点恢复。触摸端及不使用右键的用户能够从主菜单访问对应功能。

### 4.6 独立设置窗口

参考本机的“左导航 + 右侧滚动分组”，替代当前“设置范围切换 + 四图标 tab + 右侧抽屉”。

建议导航内容：

| 分类 | 保留并重新组织的设置 |
| --- | --- |
| 播放 | 倍速、播放模式、自动播放、页面隐藏时暂停、音量步长 |
| 画面 | 适应、亮度、对比度、饱和度；高级区包含 gamma、色相、锐度、缩放方式 |
| 声音 | 音量、声道、增益、平衡、延迟、均衡器、输出设备 |
| 字幕 | 可见性、字号、字体、延迟、编码、ASS 样式覆盖 |
| 外观 | 跟随系统/浅色/深色、减少动画 |
| 快捷键 | 现有按键说明；未实现自定义前提供只读列表 |
| 高级 | WASM 解码偏好、播放统计、Agent/Companion 连接信息 |

分类和分组围绕当前工程的实际能力确定，不直接复制原生所有选项。

组内使用浅底圆角区域、行间细分隔、左标签右控件；slider 用足够宽度。组标题与正文通过字号和间距区分，减少大写字距和大量边框。每组恢复默认保留，但做成低强调操作。

对话框可用原生 HTML `dialog` 或完整模态实现，必须包括焦点约束、Escape、关闭后焦点恢复，以及小屏时的滚动与全屏布局。当前即时生效语义继续保留，不增加含糊的“保存”按钮。

### 4.7 影片信息和其他对话框

URL 输入、影片信息、帮助/快捷键、错误详情统一对话框外观。媒体参数保留等宽数字和可选择文本。空状态、忙碌、失败与不支持状态使用同一套文字和颜色层级。

## 6. 桌面窗口边界

当前桌面包装是 Python 静态服务器加 Chromium `--app`，`browserHost` 只提供浏览器全屏等有限能力。

因此：

- Web 页面内的标题栏、图标、控制带、弹层和列表可以在现有架构完成。
- 普通页面 CSS 不能提供原生窗口拖动、可靠的最小化/最大化/关闭、置顶和真正的系统窗口圆角。
- 第一阶段保留宿主真实窗口按钮，避免在页面中再画一排无效按钮或出现两套标题栏。
- 如果要求整个桌面窗口也与 deepin-movie 一致，需要带窗口控制桥接的宿主；届时再统一无边框、拖动区域、窗口按钮、阴影与边缘缩放。宿主选型是单独的工程决策。

独立原型中的系统按钮只展示目标桌面外壳，不代表现有 Chromium 包装已具备这些能力。

## 7. 分阶段落实与验收

### 第一阶段：视觉骨架

完成主题变量、首页、顶栏、常驻分组底栏、应用图标方向。验收浅色首页没有 canvas 黑底覆盖；首页播放键可打开文件；有媒体后出现正确进度和时间；原有文件打开/拖放继续可用。

### 第二阶段：交互容器

实现主菜单、右键菜单、独立设置窗口、底部播放列表，迁移现有所有入口。验收菜单不越界、模态键盘行为正确、列表不挤压画面、设置即时生效、历史/书签/本地重新关联继续可用。

### 第三阶段：细节与桌面整合

补充状态动画、OSD、缩略图缓存和需要的桌面能力。缩略图预览、投屏等原本缺失的功能单列需求，不把视觉改造等同于功能已经交付。

### 验收视图与场景

- 浅色/深色：空白、打开中、暂停、播放、缓冲、失败。
- 桌面：850×600 参考尺寸，1280×800 常用窗口；窄屏：760、520、390 px。
- 设置、右键菜单、主菜单、底部列表、URL 输入和影片信息。
- 鼠标、键盘、触摸、减少动画偏好、系统主题切换。
- 使用现有真实媒体 e2e 流程验证播放、seek、音轨、字幕与持久化；保留现有性能切片设计。
